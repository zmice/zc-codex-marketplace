# 授权与执行环境复用契约

本文件统一约束 `start`、实现、并行调度、评测和验证中的交互行为。目标是完成已授权工作，同时避免重复确认、重复认证和重复初始化环境；它不改变宿主权限或代替必要授权。

## 执行前

- 先区分任务授权、宿主命令审批、系统提权、服务登录。用户同意任务不代表宿主能一次授予所有系统权限；服务登录也不能代替命令审批。
- 复用当前会话已明确授权的范围和已有可信环境，不重复向用户索取同一许可。操作对象、权限或外部影响扩大时重新判断边界。
- 先检查已有工具、依赖、安装路径、进程及验证回执。使用仓库现有工具即可完成检查时，不让包管理器自升级或临时安装工具制造额外交互。
- 批量任务启动前确定可复用环境、允许操作、唯一交互负责人和停止条件。先以一个无内容/无副作用探针确认能力，再展开批次；不能先启动全部 worker 再让用户逐个确认。

## 环境与认证

- 验证隔离不等于每个案例新建用户环境。优先复用已准备好的 runner，在同一已验证权限边界内隔离案例数据；复用前核对工具版本、配置摘要、凭据隔离和清理状态。
- Codex 的新 `CODEX_HOME`、Windows 沙箱初始化、不同宿主的审批上下文可能分别触发交互。禁止默认逐案例创建 home 并调用需要提权的初始化命令；未就绪时输出 `needs-environment`，留存准备产物。
- `windowsSandbox/readiness=ready`、权限档位可选或旧的成功回执都只是前置证据，不代表本次执行器可用。需要隔离验收时，在同一目标环境和权限档位下先运行有界、无模型的探针，核对允许读写、拒读拒写和具有可达基线的网络边界；真实命令失败或清理未确认即停，不能据 readiness 跳过失败、改用 `externalSandbox` 或切换目录重试。不同 API 的权限字段要以当前安装版本协议核实。
- 同一外部服务只保留一个待处理认证/提权请求。主线程负责向用户提供当前有效请求和具体原因，worker 不得并发创建登录链接、验证码流程或系统提权请求。
- 不声称可以“一次永久允许”所有后续操作。仅使用宿主支持且与已授权对象匹配的复用机制；不通过关闭沙箱、扩大命令前缀或更换执行通道绕过审批。

## 意外交互、失败与取消

- 第一次出现预期外确认框、认证请求或重复提权时，立即停止启动后续案例；定位触发命令、环境和权限层，不能用“再试一次”重开新环境。
- 用户说“不要再弹”“停止认证/确认”时，立即停止受影响批次和新的交互请求；继续无需新交互的本地工作。不要在等待用户处理时后台继续启动另一批。
- 配置错误、登录失效、隔离探针失败、用户取消、进程退出未确认都必须中断依赖该环境的批次。只有明确记录原因已解决，才允许恢复；单纯换目录/换参数/重新登录不算解决证据。
- 清理仅限本次拥有的进程和临时凭据；不关闭用户既有终端、IDE、浏览器或会话。清理结果未知时明确保留 `inconclusive`。
- Windows 进程树清理应在本次拥有的父进程仍可确认时执行，避免先关闭输入导致父进程退出、失去清理子树的依据。父进程后来消失不等于整棵进程树已确认清理；保留阻断记录和最少诊断，不能以新建会话绕过该状态。

## 验证与交付

- 已有新鲜可信证据满足当前改动时不重复执行同一检查。需要扩展验证时说明新增风险或未覆盖行为。
- 不能为了宣称全量通过而反复打扰用户。记录已验证、未执行、基础设施失败及行为失败，继续完成不受阻的工作。
- 必须再次请求用户参与时，只提出当前唯一阻塞项，并明确是宿主审批、系统提权还是服务认证；说明依据及为什么已有授权不能覆盖它。用户已要求停止交互时保持待处理，不再自行发起。

典型反例：为八个合成案例启动八个新 Codex home、八次沙箱初始化，再并发等待提权。正确处理：先准备并核验可复用 runner；runner 未就绪则不启动模型批次，保留本地验证结果和明确缺口。
